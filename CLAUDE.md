# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Storage is a macOS app (Rust + Tauri v2) for developers who work with coding agents. It scans the home folder and the dev-relevant folders outside it, sorts every byte into a category for a dot-matrix overview, and finds what can be cleared, with special care for the git worktrees that agents (T3 Code, Claude Code, Codex, Conductor, Cursor) create per task.

## Commands

The Rust toolchain lives in `~/.cargo/bin`; add it to `PATH` if `cargo` isn't found.

- `cargo run -p storage-app`: run the app (debug build; the UI in `ui/` is embedded at compile time, so rebuild after UI edits)
- `cargo run --release -p storage-core --example scan [-- --json]`: read-only scan from the terminal (about 6 s for a million files)
- `cargo test -p storage-core`: unit tests plus end-to-end tests against a fake home folder in a temp dir (they create real git repos and worktrees, use `Scanner::home_only()` so nothing outside the fake home is read, and `clean::clean_with` with a Trash inside the fake home so the real one is never touched)
- `cargo clippy --workspace --all-targets` and `cargo fmt --all` (120 columns, see `rustfmt.toml`)
- CI (`.github/workflows/ci.yml`, macOS runner) runs `cargo fmt --all --check`, clippy with warnings denied, the `storage-core` tests and `node --check ui/app.js`; `main` requires it to pass
- `npx @tauri-apps/cli@2 build --bundles app`: release `.app` in `target/release/bundle/macos/` (or `cargo install tauri-cli` and `cargo tauri build`)

## Architecture

- **crates/storage-core**: everything that touches the disk. No Tauri dependency.
  - `bulk.rs`: lists a folder with `getattrlistbulk(2)`, which returns names, types, allocated sizes, link counts, owners and modification times for a whole batch in one system call (a `readdir` plus an `lstat` per file is what makes a big walk slow). Falls back to `lstat` where the file system doesn't support it; a test checks the two agree.
  - `scan.rs`: one parallel `rayon` walk of `$HOME` plus `rules::SYSTEM_ROOTS` (/Applications, /Library/Developer, Homebrew, /tmp, …) and the per-user temp and cache folders under /var/folders (16 threads; the walk waits on the kernel, so more threads than cores helps). Paths are home-relative inside home and absolute outside it; outside roots are `quiet` (root-owned folders aren't reported as unreadable). Simulator runtimes can't be walked, so `sim_runtimes` asks `simctl runtime list -j` (only when a full Xcode is selected, to avoid the install prompt) while the walk runs, and each worktree is inspected by git while its files are counted. `Scanner::cancel` stops a scan early; the report it then returns is partial and must be thrown away. Sizes are allocated bytes, hard links are counted once, other volumes and symlinks are skipped. Every file adds to exactly one `Cat` (the test asserts `scanned == sum(cats)`). Folders matching a rule become `Entry`s, in `match_dir` priority order: `SKIP` → `FIXED` → `CHILDREN_OF` → `GRANDCHILDREN_OF` → path patterns → project patterns (`pat_ok`: only outside `Library`, `Applications` and top-level dot folders, or anywhere inside a worktree). Once a folder matches, nothing beneath it can match (`claimed`). Temp-folder rules set `min_age`, so anything touched in the last day is skipped (Downloads uses the same mechanism with three months); a folder's own modification time and its subfolders' count as well as its files', so one unpacked today from an archive of old files isn't offered. Ollama tags that share their weights (an alias, or a model built `FROM` another) are one entry whose command removes them together, sized by the blobs nothing outside the group uses. Entries carry a `hold` reason when they shouldn't be swept up without a second look: a cache whose app is running (`sys::running_apps`, from `lsappinfo`), the default rustup/nvm/pyenv version, or a simulator that is booted. The UI never suggests those or selects them with their group, and warns before clearing them. An entry can `spare` one child folder (Claude Code's per-project `memory`), which is kept and not counted. Each entry also remembers its device and inode, when it was scanned and its `min_age`, for the checks cleanup repeats. Entries are complete when pushed, so `Scanner::entries_from` lets the shell stream them while the scan runs. Nothing inside an app bundle or a `.git`/`.hg`/`.svn` folder is ever an entry. The exception is a linked git worktree (a `.git` file pointing into `…/.git/worktrees/`): it's an entry, its contents count as `Cat::Worktrees`, and its build output, `node_modules` and venvs are entries too, with `parent` set to the worktree's key.
    The walk also returns a pruned `Node` tree for the drill-down view (`MIN_NODE`, `MAX_CHILDREN`, `MAX_TREE_DEPTH`; leftovers fold into an `o` aggregate). Its root, "This Mac", holds one node per scan root, the simulator runtimes and a virtual (`x`) node for the part of the disk that wasn't scanned. Node keys are short (`n`, `s`, `t`, `c`, `p`, `f`, `o`, `u`, `x`) because the tree is sent to the UI whole.
  - `rules.rs`: categories, recommendations (`RECS`) and the path tables. Project build folders are either unambiguous names (`BUILD_DIRS`), names that only count next to a marker file (`BUILD_WITH`: `target` beside `Cargo.toml`), or one disposable subfolder of a folder that also holds state (`BUILD_INSIDE`: `.wrangler/tmp`, never `.wrangler/state`). `Safe` is only for what a named tool rebuilds; generic app caches, logs, `~/.cache`, Maven's and conda's stores are `Review`. Old CLI releases beside a `current` link only match under `AGENT_PACKAGES` (just `~/.codex/packages/`), because deploy folders are laid out the same way and agents' other folders hold worktrees. `Tier::Safe` means regenerated automatically, `Tier::Review` means the user decides. `child_cat` decides a folder's category: worktree > matched rec > `CAT_PATHS` > parent.
  - `git.rs`: worktree detection and a read-only inspection (`GIT_OPTIONAL_LOCKS=0`): branch, uncommitted files, commits only on a detached HEAD, ignored files that aren't regenerable (`.env`), merged into the default branch, upstream pushed or `[gone]` (squash-merged PRs), locked, last activity. A failed or timed-out git command sets `unknown` and a missing git record sets `orphaned`; neither is ever treated as clean. Each inspection also records HEAD and a digest of `git status` (with the changed files' sizes and times), which cleanup compares with a fresh one. The status call is `--porcelain=v2 -z --untracked-files=all --ignored=matching`, so the digest sees staged object ids, real file names, files inside untracked folders and ignored files; each listed path adds its length and nanosecond mtime, and a folder adds the same for everything in it by name. If that walk can't finish (unreadable, or over `STAMP_BUDGET` entries) or a file won't give up its attributes, the result is `partial` (and `unknown`), cleanup always refuses, and the UI doesn't offer the worktree. `rescue` points a ref (`refs/storage/trashed/<name>-<commit>`) at a detached HEAD that has commits nothing else holds, before its worktree is trashed, and `rescue_index` saves anything staged as a commit under `…-staged-<commit>` (the index goes with git's record whenever git next prunes it); when that can't be done the record is locked instead, and the lock is taken off again if the move doesn't happen. `forget` removes git's record of that one worktree (not a repo-wide `worktree prune`), and only when it held nothing uncommitted: with changes, the record (index included) is what makes a folder put back from the Trash work again.
  - `remove.rs`: `rm -rf` that can't be redirected: every folder is opened relative to its parent with `O_NOFOLLOW` and emptied through that descriptor (folders on the way down are only opened `O_SEARCH`, which the Trash allows without Full Disk Access), read-only folders are made writable, a folder on another volume is refused, and sibling subtrees go in parallel (about twice as fast as `std::fs::remove_dir_all` on `node_modules`).
  - `clean.rs`: acting on entries. Safe → deleted (`remove::remove_under`); Review → moved to the Trash via NSFileManager; entries with `cmd` (simulators, Ollama) run that command under a time limit; Docker usage is reported with a hold reason, but cleanup refuses its global prune because the scan has no object inventory (the stored command remains pinned to Docker Desktop's context); the Trash rec empties `~/.Trash` (`remove::empty_under`, which refuses a Trash that is a symlink). Without Full Disk Access macOS won't list `~/.Trash` (or open it for reading) but lets what is in it be removed by name, so the scan reports `trash_readable: false` and offers no Trash entry; after a cleanup the shell adds one whose `trashed` lists where each item Storage moved there went (`clean_noting`, from the held object's path afterwards), and emptying that entry removes only those items, by name and inode, leaving anything put back, trashed from Finder or replaced alone. `plan` puts emptying the Trash before anything is moved into it. Every path goes through `guard`: inside home and not a protected top-level folder, or outside home only in /tmp, the user's /var/folders temp and cache folders, or a whole app in /Applications, and owned by the user; never a symlink, and never reached through one. Then `recheck` repeats the scan's reasons, since the report can be hours old, on the principle that cleanup only acts on what the user was shown: same device and inode, nothing written since the scan to a file or folder offered for being stale (a folder that can't be read through, or holds more than `MTIME_BUDGET` entries, is refused with its own reason), an old CLI version that hasn't become current, a version that hasn't become the default, editor state whose project folder (from `workspace.json`) is still gone, a cache whose app hasn't been started (the running apps are asked afresh for every cache entry, never remembered across a batch), a simulator that is shut down and unused since (`lastUsedAt` in its `device.plist`; unreadable means no), and for a worktree a fresh look that stops if anything is now running in it (`lsof`; not being able to ask also stops it; `sys::process_cwds` leaves out the commands Storage started itself, so the `git` a scan runs inside a worktree never reads as someone working there) or if its commit, branch or changed files differ, if git's record of it appeared or disappeared, if git couldn't inspect it at the scan but can now, or if either look was incomplete. An entry with a spared folder is trashed as one sibling folder holding everything else, put back if the move fails, without ever replacing a file written there in the meantime (`rename_new`). The Trash takes a path, so the checked object is held open (`remove::hold`) across the move and must have gone somewhere; where it went is what `trashed` records.
  - iCloud/File Provider folders (`CLOUD_ROOTS`) can hang when listed, so each child is measured with `du` under a timeout.
- **src-tauri**: thin shell. Commands: `scan` (streams `Progress` over a `Channel`), `clean` (takes entry *keys*, never paths; looks them up in the stored report), `cancel` (stops the running scan, which then fails with `"cancelled"` and leaves the previous report in place, or stops a cleanup after the item it's on), `disk`, `reveal` (an entry), `reveal_path` (a tree node; only reveals in Finder), `recs`, `full_disk_access`, `reveal_log`, `grant_access`. `grant_access` (`access.rs`) opens the Full Disk Access pane and, unless access is already there, floats a native non-activating `NSPanel` (objc2) under the System Settings window (found with `CGWindowListCopyWindowInfo`, which needs no Screen Recording access) holding the app's icon: dragging it drags the `.app` bundle's file URL into the list. A main-run-loop timer keeps it beside that window until it's moved by hand, shows it only while System Settings is frontmost, checks access once a second and emits `full-disk-access` when it arrives (the UI then rescans), and closes it when System Settings quits. One scan or cleanup at a time (`Busy`). Every cleared item is appended to `~/Library/Logs/Storage/cleanup.log`. Debug builds can be driven end to end against a throwaway home: `HOME=<dir> STORAGE_UI_SCRIPT=<file.js> STORAGE_UI_REPORT=<out> target/debug/storage` runs the script in the window after load, `dev_report` writes what it found, and the Trash used is the one in that home (a release build ignores all of it).
- **ui/**: vanilla JS/CSS, no build step, no external resources (strict CSP). `DotBar` draws the canvas: dot-matrix segments per category, hover highlight, scan edge and the particle dissolve when something is cleared. It draws at full rate only while something changes, keeps the idle shimmer going at a low rate for a few seconds after the last change or hover, then holds still; it draws nothing while the window is hidden or unfocused, the bar is scrolled away or reduced motion is on (`wake()` after changing anything it shows). The model in `S` is updated optimistically from clean events; Docker sizes are left alone because its disk image doesn't shrink right away. A rescan keeps the current results on screen until the new report arrives and sweeps the bar by progress (files counted against the last scan's total, kept in `localStorage`); only the very first scan fills the bar from nothing. The hero footer is one state machine (`renderSuggest`): the first-launch note when Full Disk Access is missing, scanning, cleaning with progress and Stop, the cleanup result with per-item errors, or the suggestions pager, whose first page clears everything safe in one step. `autoOk` decides what a suggestion or group checkbox may pick up (not in use, not held, not kept, not used in three days; a group with nothing eligible can't be ticked as a whole); `wtRemovable` is the stricter "finished" test for worktrees (git answered, nothing uncommitted, unsaved or ignored-but-irreplaceable, merged or upstream gone, not in use). The list has three tiers by how things leave (deleted, trashed, removed for good by a tool), details are built only for open rows, and the confirm dialog names every item and every risk. After a cleanup the headline numbers come from the system (`summary.disk`), not from sums of what was cleared. The selection is cleared whenever a new report arrives. `localStorage` holds the last scan's totals and entries (shown, inert, at the next launch until the new scan lands), the kept entries, and whether the access note is hidden. The Explore tab is a squarified treemap of the scan tree (two levels at a time, Escape to go up); tiles that are entries get a checkbox that shares the selection, and `treeAdjust` shrinks the tree as things are cleared. Suggestions are grouped by recommendation category and skip anything used in the last three days or inside a worktree active in the last two hours.

## Verifying UI changes

No browser automation is set up. Check JS syntax with `/System/Library/Frameworks/JavaScriptCore.framework/Versions/Current/Helpers/jsc -e "checkSyntax('ui/app.js')"`. For screenshots, either run the app and capture its window (`screencapture -l <window id>`), or load `ui/` in a WKWebView from a small Swift script with a mocked `window.__TAURI__` that returns the JSON from the `scan` example. WebKit stops `requestAnimationFrame` and reports `document.hidden` when the window is off-screen, occluded or the display is asleep, and the bar honours that, so the script should give the window an on-screen frame above other windows (alpha can be near zero) and replace `requestAnimationFrame` and `document.hidden` in the mock.
